## One-line answer

Softmax turns raw scores into probabilities that sum to 1, and temperature is a single number
dividing the scores before it — squashing the distribution towards certainty below 1 and towards
uniformity above it.

## The story

Back at the suggestion strip, but now with a dial on the side of the keyboard.

Turn it fully one way and the keyboard becomes stubborn: it offers the same safe word every time,
the one it is most sure about, and typing the same opening twice gives the same sentence twice.
Turn it the other way and it becomes reckless — offering words that have almost nothing to do with
what you wrote, cheerfully.

The dial changes nothing about what the keyboard knows. The rankings underneath are identical at
every setting. All the dial does is decide how much the gaps between them matter.

## The idea in plain language

**Softmax** takes a list of real numbers and returns a list of positive numbers summing to 1, while
keeping the order intact. For a list of logits *z*, the probability of item *i* is
`exp(z_i) / Σ exp(z_j)` — exponentiate everything, then divide by the total so it sums to 1.

Two properties are worth carrying forward.

**Only differences matter.** Add the same constant to every logit and the result is unchanged: the
constant factors out of the top and bottom. This is why the absolute values from part
[2.1](2.1-from-string-to-logits.md) — all between −85 and −57 — looked odd but were fine. A logit
on its own means nothing.

**It exaggerates.** Because of the exponential, a logit that is 3 higher than another becomes about
20 times more probable. Small gaps in score become large gaps in probability.

**Temperature** is a number *T* the logits are divided by before softmax: `softmax(z / T)`.

- `T = 1` — the distribution as the model produced it.
- `T < 1` — dividing by a small number *magnifies* the gaps, so the leader pulls away. The
  distribution sharpens towards certainty. `T → 0` is picking the top token every time.
- `T > 1` — dividing by a large number *shrinks* the gaps, so everything moves closer together. The
  distribution flattens towards uniform, and unlikely tokens get a real chance.

The thing to hold on to: **temperature does not change what the model believes.** It changes how
decisively that belief is acted on. The ranking is identical at every temperature; only the spacing
moves.

## Why Yantra needs it

Temperature reappears in a role that catches people out. On day 86, knowledge distillation uses a
*high* temperature on the teacher's logits deliberately — because a flattened distribution reveals
which wrong answers the teacher thought were nearly right, and that structure is most of what the
student is learning. The same dial, used for the opposite purpose.

Sooner: day 210 builds prompt regression tests, and a test against a model sampling at `T > 0` is
flaky by construction. Knowing that `T = 0` is the reproducible setting is what makes those tests
possible at all.

## The mechanism

Take one set of logits and read the same beliefs at three settings.

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

tok = AutoTokenizer.from_pretrained("distilgpt2")
model = AutoModelForCausalLM.from_pretrained("distilgpt2"); model.eval()

ids = tok("The capital of France is", return_tensors="pt").input_ids
with torch.no_grad():
    last = model(ids).logits[0, -1]

for T in (0.1, 1.0, 2.0):
    p = torch.softmax(last / T, dim=-1)
    top = torch.topk(p, 3)
    row = "  ".join(f"{tok.decode([i])!r}:{v*100:5.1f}%"
                    for v, i in zip(top.values.tolist(), top.indices.tolist()))
    print(f"T={T:<4} {row}")
```

**Line by line:**

- `last / T` — the entire implementation of temperature. It happens **before** softmax; dividing
  the probabilities afterwards would break the sum-to-1 property and is a real bug people write.
- `torch.softmax(..., dim=-1)` — `dim=-1` normalises across the vocabulary axis. On a 1-D tensor
  this is the only choice, but on the `(batch, seq, vocab)` tensor from part 2.1 the wrong `dim`
  normalises across positions instead and produces confident nonsense. Always name it.
- `torch.topk(p, 3)` — three, to match the phone strip. The distribution still has all 50257
  entries at every temperature.
- The loop reuses **one** `last` tensor — the model is called once. This is what makes the
  comparison honest: the beliefs are identical and only the reading changes.

Its real output:

```text
T=0.1  ' the': 97.3%  ' home':  2.7%  ' now':  0.0%
T=1.0  ' the': 11.8%  ' home':  8.2%  ' now':  5.0%
T=2.0  ' the':  0.7%  ' home':  0.6%  ' now':  0.4%
```

*Observed 2026-09-07 · `distilgpt2` · torch 2.14.0+cpu · transformers 5.16.1.*

Read across the rows and notice what did **not** change: `' the'`, `' home'`, `' now'` are in that
order at every temperature. One forward pass, one set of beliefs, three readings.

At `T=0.1` the leader holds 97.3% and third place has rounded to zero — the model will say `' the'`
essentially always. At `T=2.0` the leader has 0.7%, meaning 99.3% of the probability is spread
across the other 50256 tokens. That is not creativity; that is a model being outvoted by noise.

## When it breaks

Setting temperature to exactly zero does not sharpen the distribution — it divides by zero:

```text
$ python -c "
import torch
z = torch.tensor([1.0, 2.0, 3.0])
print(torch.softmax(z / 0.0, dim=-1))
"
tensor([nan, nan, nan])
```

*Observed 2026-09-07 · torch 2.14.0+cpu.*

**What it means:** `z / 0.0` gives `inf` for positive logits and `-inf` for negative ones, and
softmax over infinities is `inf/inf`, which is `nan`. No exception is raised. The `nan` propagates
into sampling and the failure surfaces somewhere else entirely.

**What actually happens in real code:** every serving stack special-cases it. `temperature=0` in an
API is not passed to this formula — it is intercepted and turned into greedy selection, taking
`argmax` and skipping softmax entirely. It is a naming convention, not arithmetic.

**The smallest fix:** branch on it. `if T == 0: token = logits.argmax()` before any division. Part
[2.3](2.3-the-loop.md) uses exactly that path.

## In production

- **What a professional writes instead of the teaching version.** Temperature is rarely used alone.
  It is paired with **top-k** (consider only the k highest-scoring tokens) or **top-p**, also called
  nucleus sampling (consider the smallest set whose probabilities sum to p). The reason is visible
  in the `T=2.0` row above: raising temperature gives probability to the entire tail, including
  tokens that are simply wrong. Top-p truncates that tail first, so temperature redistributes only
  among plausible candidates. Day 111 needs this when constraining output to valid JSON.
- **What degrades at scale.** Sampling at `T > 0` makes outputs non-reproducible, which breaks
  caching. Two identical requests produce different responses, so a semantic cache — day 144 —
  cannot serve the second from the first without changing behaviour. Teams discover this when their
  cache hit rate is near zero and nobody can say why.
- **The failure that only shows with real traffic.** Temperature interacts with prompt length in a
  way that only appears in production. Long retrieved contexts tend to produce sharper
  distributions, so a temperature tuned on short prompts behaves differently once the RAG pipeline
  starts filling the window — the same setting is effectively cooler.
- **The review comment.** *"This eval runs at `temperature=0.7`. The scores will move between runs
  and we can't tell a regression from noise — pin it to 0."*
- **The interview question.** *"What does temperature actually do to the model?"* The answer that
  ends it: nothing. It rescales the logits before softmax. The model's beliefs and their ordering
  are unchanged; only the decisiveness of the sample changes.
